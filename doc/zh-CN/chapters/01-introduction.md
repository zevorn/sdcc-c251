# SDCC 简介

## 关于 SDCC

SDCC（Small Device C Compiler）是一套自由、开源、可移植到不同目标且具备优化
能力的 C 编译工具链，主要面向资源受限的微处理器和微控制器。它最初由 Sandeep
Dutta 编写，当前支持 Intel MCS-51 系列、Dallas DS80C390、HC08/S08、Z80 及其
相关处理器、STM8、Padauk PDK、MOS6502 等架构。本下游分支还提供 MCS-251 后端。

SDCC 不只是一个 C 编译器。完整套件还包括预处理器、ASxxxx 派生汇编器和链接器、
库管理工具、Intel HEX 工具、运行库、ucSim 模拟器以及 SDCDB 调试器。各组件许可
不同，使用或再分发前应查看对应源码文件的许可证声明。

编译器除目标相关优化外，还会执行常量折叠与传播、公共子表达式消除、循环不变量
外提、归纳变量强度削弱、复制传播、无用代码删除、寄存器分配、跳转表生成和基于
规则的 peephole 优化。优化结果受目标指令集、内存模型、别名信息以及代码尺寸或
速度偏好影响。

SDCC 主要数据类型通常如下；个别后端的实现限制以目标章节为准。

| C 类型 | 常见宽度 | 说明 |
|---|---:|---|
| `_Bool` / `bool` | 1 字节 | 取值为 0 或 1 |
| `char` | 1 字节 | plain `char` 的符号性由目标定义 |
| `short` / `int` | 2 字节 | 通常为 16 位 |
| `long` / `float` | 4 字节 | `float` 接近 IEEE 754 binary32 |
| `long long` | 8 字节 | 某些后端支持不完整 |
| `_BitInt` | 1 至 8 字节 | 支持范围依后端而异 |
| 指针 | 1 至 4 字节 | 宽度和编码由地址空间及目标决定 |
| `__bit` | 1 bit | 只在具有相应位地址空间的后端提供 |

编译器允许在 C 函数中嵌入汇编，也允许 C 与独立汇编模块互相调用。此类代码必须
遵守目标 ABI、符号命名、参数传递、返回值、寄存器保存和栈约定。

## 许可证

SDCC 是多个来源不同的自由软件组件集合，不能用一个许可证概括全部内容。

- `sdcc` 编译器主体采用 GPL。编译器生成的 C 程序或目标文件不会仅因使用 SDCC
  而自动受 GPL 约束。
- `sdcpp` 源自 GCC 预处理器；`sdas`/`sdld` 源自 ASxxxx；`sdar` 等工具源自 GNU
  Binutils。其确切许可证以当前源码为准。
- 大多数 SDCC 运行库使用带链接例外的 GPL，允许与闭源程序链接；少数器件头文件
  和库位于 non-free 树，必须遵守厂商附加条件并显式启用。
- ucSim、SDCDB、文档和各辅助工具可能采用不同许可证。

发布产品前应检查实际链接的库、复制的启动代码、器件头文件和构建工具，而不是只
检查编译器可执行文件。

## 文档和排版约定

英文规范手册位于 `doc/sdccman.lyx`，快照 PDF 发布在 SDCC 网站。中文手册位于
`doc/zh-CN/`，保持独立目录以便同步主线。

本文使用以下约定：

- `等宽字体`表示命令、选项、文件名、路径、C 标识符和汇编符号；
- *斜体*用于第一次出现的概念或强调；
- 命令示例中的 `$` 或 shell 提示符不是命令的一部分；
- 目标名称写作 `mcs51`、`mcs251`，架构名称写作 MCS-51、MCS-251；
- 十六进制地址通常写作 `0x1234`，位范围写作 `15:8`。

## 版本兼容性

SDCC 不承诺不同版本之间始终保持目标文件或 ABI 兼容。命令行选项、运行库布局、
调试格式、调用约定和默认优化都可能演进。升级时应重新编译所有翻译单元和运行库，
不要把旧 `.rel` 文件与新工具链混合链接。

从旧版本迁移时，应先保存原构建的 `sdcc --version`、完整命令行、链接 map 和测试
结果，再在新版本上执行干净构建。对 MCS-51 应特别检查通用指针标签、内存模型和
banked 调用；对 MCS-251 还应检查 ABI revision、24 位重定位和运行库模型目录。

## 系统要求和其他资源

构建 SDCC 通常需要符合要求的宿主 C/C++ 编译器、GNU Make 或兼容 make、Bison、
Flex、Boost，以及目标相关的可选依赖。构建文档还需要 LyX/LaTeX；本中文版本使用
Pandoc、XeLaTeX 和 CJK 字体。

可参考的上游资源包括 SDCC 网站、SourceForge 项目页、邮件列表、Wiki、bug tracker
和每日快照。第三方示例、博客和器件包可能针对旧版本，使用前应核对目标名、语法、
内存布局和许可证。
