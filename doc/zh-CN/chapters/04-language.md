# SDCC 语言扩展

## 命名地址空间

许多微控制器拥有彼此独立、由不同指令访问的地址空间。SDCC 使用命名地址空间把
这一硬件事实带入 C 类型系统。MCS-51/DS390 常见修饰符包括：

| 修饰符 | 含义 |
|---|---|
| `__data` / `__near` | 快速内部数据空间 |
| `__idata` | 间接寻址内部数据空间 |
| `__pdata` | 分页外部数据窗口 |
| `__xdata` / `__far` | 外部或远数据空间 |
| `__code` | 只读代码空间 |
| `__bit` | 位地址空间 |
| `__sfr` / `__sbit` | SFR 和可位寻址 SFR |

对象空间和指针对象自身空间是两个不同概念：

```c
__xdata unsigned char * __data p;
```

这里 `p` 自身位于 `__data`，指向的字节位于 `__xdata`。把修饰符写在错误一侧会
改变类型、指针宽度和生成指令。

MCS-51 的通用指针带地址空间标签；MCS-251 revision 1 的三字节通用指针是无标签
24 位平坦地址。两者不能混用。Z80、HC08、PDK、MOS6502 等后端只实现与各自硬件
有关的地址空间，不能假定 MCS-51 关键字在其他目标含义相同。

## 绝对地址

`__at(address)` 可把对象放到绝对地址，常用于寄存器、引导协议或共享内存：

```c
__sfr __at (0x90) P1;
__xdata unsigned char __at (0x8000) mailbox;
```

绝对地址绕过常规分配，链接器无法自动发现所有重叠。地址必须来自具体芯片手册和
链接布局；库代码不应无条件占用应用地址。

## 启动钩子

应用可实现 `__sdcc_external_startup()`，在普通数据初始化和 `main` 之前执行目标
相关设置。它适合时钟、外部 RAM 或看门狗配置，但执行时 C 运行环境尚未完全建立，
不得依赖未初始化的全局对象或普通库调用。返回值控制是否执行默认 XINIT 初始化，
具体约定以目标启动代码为准。

## 寄存器保存说明

函数声明可使用目标支持的 preserved register 说明，帮助编译器了解外部汇编函数的
寄存器破坏集合。错误声明会产生静默的数据损坏，比保守地保存寄存器更危险。只有在
汇编实现和所有调用路径都经过验证时才使用。

## 常量和参数扩展

SDCC 支持二进制常量、目标相关的参数提升控制、参数前置声明以及部分新标准扩展。
这些语法可能不是可移植 ISO C；公共头文件应通过 `__SDCC` 和目标宏隔离，或提供
标准 C 备选实现。

## 参数和局部变量

资源受限目标常把第一个参数或返回值放入固定寄存器，其余参数可能位于静态参数区、
overlay 区或栈。默认自动变量也可能采用静态分配，而不是桌面 C 编译器常见的每次
调用栈帧。

递归、函数指针间接调用、中断重入或多上下文调用必须使用目标支持的可重入约定。
`__reentrant` 只改变所声明函数；`--stack-auto` 改变整个翻译单元的默认约定。二者
都属于 ABI，库和调用者必须匹配。

## overlay

链接器可根据调用图让不会同时存活的静态参数和局部区域共享地址，这称为 overlay。
它能显著节省内部 RAM，但依赖调用图完整且函数不可重入。以下情况会破坏这一前提：

- 递归或相互递归；
- 通过函数指针调用而链接器无法确定目标；
- 同一函数既被主程序调用又被中断调用；
- 汇编入口未在调用图中表示；
- 并发执行环境。

可用 `__reentrant`、`--stack-auto` 或 `--nooverlay` 选择更保守的分配。不要只为消除
一个症状关闭 overlay，而应先确认真实重入关系。

## 中断服务例程

中断函数使用 `__interrupt(n)` 声明，后端负责生成目标规定的返回指令和必要入口。
部分目标支持 `__using(n)` 选择寄存器 bank。中断号、向量位置、优先级和保存集合
由芯片决定，不是 C 语言统一属性。

```c
void timer0_isr(void) __interrupt(1) __using(1)
{
    tick_pending = 1;
}
```

中断共享对象通常必须为 `volatile`，但 `volatile` 不提供原子性。多字节对象在 8 位
CPU 上可能被主程序和中断交错访问，应使用临界区、单生产者协议或芯片原子操作。
中断中调用非可重入库函数、耗时浮点运算或深调用链还可能导致状态破坏和栈溢出。

## 临界区和中断控制

`__critical` 可用于函数或语句块，后端会保存并控制中断使能状态。临界区应尽量短，
并考虑嵌套语义；手写开关中断代码若无条件重新使能，可能破坏调用者原来的状态。

## 私有寄存器 bank

MCS-51 的 `__using(n)` 让函数使用指定寄存器 bank，常用于减少中断入口保存开销。
主程序、启动代码和多个中断必须统一分配 bank；同一 bank 被可嵌套中断共享会损坏
寄存器。MCS-251 有更大的寄存器文件和不同 ABI，不应照搬 MCS-51 bank 策略。

## 内联汇编

新式内联汇编使用编译器可理解的操作数和约束时，编译器才能正确处理寄存器、数据流
和优化。旧式 `__asm ... __endasm` 更接近不透明文本，适合短小、经过审查的序列。

```c
void idle_once(void) __naked
{
    __asm
        nop
        ret
    __endasm;
}
```

`__naked` 禁止普通序言和结尾。使用者必须亲自完成参数访问、寄存器保存、栈平衡和
返回；普通函数不应为了减少几条指令而使用它。

## 算术支持和运行库

目标没有硬件乘除或浮点单元时，编译器会调用运行库辅助函数。函数名、参数布局和
寄存器破坏集合是内部 ABI，不建议应用直接调用。整数提升、除零、带符号溢出和浮点
舍入仍遵循 C 语义及目标实现说明。

标准头和运行库提供目标可负担的 `stdio.h`、`stdlib.h`、`string.h`、`math.h` 等
子集。格式化 I/O 尤其占用代码和栈，链接前应检查 map。线程安全、locale、文件系统
和宿主环境相关功能可能缺失或由用户提供底层钩子。

## 内存模型

内存模型是编译器为未显式修饰对象选择默认空间的策略，不等同于芯片手册中的物理
存储模式。模型会影响指针、参数区、启动对象和运行库，属于全程序 ABI。MCS-51 和
MCS-251 的具体模型分别见后续章节。

## pragma 和预定义宏

`#pragma` 可控制目标、优化或代码段行为。未知 pragma 的诊断取决于方言和选项；
可移植头文件应限制作用域并记录恢复方式。编译器定义 `__SDCC`，各后端还定义自己的
宏，例如 `__SDCC_mcs51` 和 `__SDCC_mcs251`。不要用用户自定义宏冒充目标宏。
