# MCS-251 后端

## 身份和兼容边界

| 项目 | 值 |
|---|---|
| 编译选项 | `-mmcs251` |
| 预定义宏 | `__SDCC_mcs251` |
| ABI revision | `1` |
| 汇编器 | `sdas251` |
| 运行库 | `mcs251.lib` |
| 对象格式 | ASxxxx `.rel` |
| 固件格式 | Intel HEX |
| 默认指令映射 | MCS-251 Source mode |

目标名只使用 `mcs251`。本分支不提供 `-mc251` 或 `__SDCC_c251`，也不承诺与 Keil
C251 源码、OMF-251 对象或库兼容。Keil 示例只用于理解行为，仓库测试按 SDCC 风格
重新编写。

## 最小程序

```c
#include <stdint.h>

volatile __xdata uint32_t counter;

void main(void)
{
    for (;;)
        ++counter;
}
```

```sh
sdcc -mmcs251 --model-small -o firmware.ihx main.c
sdcc -mmcs251 --model-large -o firmware.ihx main.c
```

当前正式支持 small 和 large。共享帮助表可能显示 medium/huge 名称，但 MCS-251
后端不会接受它们作为受支持模型。

## Source mode 和 Binary mode

MCS-251 对部分 opcode 有两套映射：Source mode 优先解释原生 MCS-251 指令，冲突
的经典 MCS-51 指令使用 `0xA5` 前缀；Binary mode 优先保持 MCS-51 二进制编码。

本后端默认生成 Source mode 代码，启动代码不修改 `AUXR2.CPUMODE`。固件或
bootloader 必须保证 CPU 以 Source mode 进入。模式错误会让同一字节流获得完全
不同的指令语义。

`sdas251` 覆盖两套映射、已记录的 MCS-251 指令形式、重定位和范围诊断。编码测试
位于 `sdas/as251/tests/`。完整清单、正向/反向测试和编译器覆盖边界见
[MCS-251 指令集支持](12-mcs251-instruction-set.md)。

## 数据和指针

ABI revision 1 采用处理器原生的 big-endian C 对象布局：多字节 scalar 的最高
有效字节位于最低 memory address，原生 WR/DR register tuple 的最低编号 register
也保存最高有效字节。`-mmcs251` 不提供 little-endian 模式；`-mmcs51` 仍保持其
既有 little-endian ABI。

| 指针种类 | 大小 | 表示 |
|---|---:|---|
| `__data` / `__idata` near 指针 | 1 字节 | region 00 page-zero 地址 |
| `__pdata` 指针 | 1 字节 | 当前 `MXAX:P2` 页偏移 |
| `__xdata` / `__far` 指针 | 3 字节 | 平坦 24 位地址 |
| `__code` 指针 | 3 字节 | 平坦 24 位代码地址 |
| 通用指针 | 3 字节 | 无地址空间标签的平坦地址 |
| 函数指针 | 3 字节 | 24 位代码地址 |

三字节 pointer object 在递增地址上按高、中、低字节保存。DPX 的 DPL、DPH、
DPXL 则是 hardware address register 的组成部分，分别对应位 `7:0`、`15:8`、
`23:16`。通用指针不能表示独立直接 SFR 窗口；SFR 继续通过 `__sfr`/`__sbit` 直接
访问。

## 内存模型

| 选项 | 普通对象默认位置 | 运行库目录 |
|---|---|---|
| `--model-small` | region 00 page-zero edata | `mcs251-small` |
| small + `--stack-auto` | 静态对象 edata，自动对象 SPX 栈 | `mcs251-small-stack-auto` |
| `--model-large` | XSEG 平坦数据空间 | `mcs251-large` |
| large + `--stack-auto` | 静态对象 XSEG，自动对象 SPX 栈 | `mcs251-large-stack-auto` |

默认 XSEG 从 `0x010000` 开始，避免 far/generic 指针与 page-zero edata 混淆，并
匹配当前 STC32G QEMU 机器。不同板级可用 `--xram-loc` 覆盖。

## 调用、返回和栈

普通 C 调用统一使用 24 位控制流：

- 直接调用 `ECALL`；
- 尾调用或远跳转 `EJMP`；
- 普通返回 `ERET`；
- 中断返回 `RETI`。

即使调用双方在同一 64 KiB region，也不把普通 C 调用缩短为 `LCALL`/`RET`，从而
保证独立对象重新布局后 ABI 仍成立。

硬件栈由 16 位 SPX 寻址并向高地址增长。自动对象和可重入参数使用
`@SPX+dis16`。默认约定保留 overlay 参数区；无法全部放入寄存器的间接调用要求
函数指针和目标为 `__reentrant`，或全程序统一 `--stack-auto`。

## STC32G QEMU 固件

QEMU 使用 24 位 Intel HEX 地址。典型布局：

```sh
sdcc -mmcs251 --model-small --debug --no-xinit-opt \
    --code-loc 0xff0000 '-Wl-b GSINIT0=0xfc2800' \
    -o firmware.hex firmware.c
```

```sh
qemu-system-mcs251 \
    -M stc32g144k246-evb -bios firmware.hex \
    -display none -monitor none -serial stdio
```

手动端到端测试覆盖 Timer0/1、UART1、GPIO、外部中断、DSP32 和 TFPU 的已实现
子集。主 CI 只保留 UART smoke test，避免把外设实现变成编译器门禁。QEMU 不是
cycle-exact，未建模外设不能因为编译成功就宣称运行通过。

## 自动测试

```sh
make -C build/sdas/as251 check
make -C build/src/mcs251 check
make -C build/support/valdiag test-mcs251
make -C build/src/mcs251 check-uart-qemu \
    QEMU_MCS251="$HOME/oss/qemu/builds/build-mcs251/qemu-system-mcs251"
```

前三个入口分别验证汇编器/链接器、编译器 code generation 和四种配置的语言诊断；
UART 只负责确认代表性固件可以执行并通信。`check-qemu` 仍可手动运行 ABI、内存模型、
官方示例语义、外设和 GDB stub 扩展测试。ABI 修改还必须执行 MCS-51 非回归，防止
共享后端变化泄漏。
